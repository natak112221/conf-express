# Практика 4. Подсистема безопасности ИС

## Что было до

Проверочный скрипт `portal/tools/security-check.js` на первой версии портала (практика 3) не прошла 7 проверок из 12: пароли в базе открытым текстом, нет заголовков безопасности, у cookie нет SameSite, форма смены статуса принимала запрос без токена (код 302), перебор пароля не ограничен. Снимки: `01-до-пароли-в-базе.png`, `02-до-проверка-безопасности.png`.

## Что сделала

| Требование | Что сделано |
|---|---|
| Хеширование паролей | bcryptjs, 10 раундов. Миграция `002_security.js` превращает уже сохранённые пароли в хеши, новые хешируются при создании пользователя |
| SQL-инъекции | все запросы с `?` (prepared statements), строки в SQL не склеиваются; проверка: логин `' OR '1'='1' --` не пускает |
| Права доступа | гость видит только мероприятия, участник заявки только свои, `/admin` закрыт для всех кроме администратора (403), проверка на сервере в `middleware/auth.js` |
| Проверка данных | на сервере `lib/validate.js`, в браузере атрибуты `required`, `minlength`, `pattern`, `type=email` |
| Сессии и cookie | свой `sid` с флагами HttpOnly и SameSite=Lax (Secure включается на https переменной `COOKIE_SECURE=1`), сессии в SQLite, новый идентификатор после входа, срок 2 часа |
| Подделка запроса | токен в сессии и в скрытом поле каждой формы, без него ответ 403 |
| Перебор пароля | 5 неверных попыток за 10 минут закрывают вход по этому логину (код 429) |
| Заголовки | helmet: Content-Security-Policy, nosniff, без X-Powered-By |

## Как проверила

- `node tools/security-check.js`: 12 из 12 (снимок `04-после-проверка-безопасности.png`).
- `npm test`: 12 тестов, в том числе на безопасность (`05-тесты-безопасности.png`).
- Миграцию паролей запустила на копии базы из практики 3: было `Admin2026`, стал хеш `$2b$10$...` (`03-после-миграция-паролей.png`).
- В браузере: неверный пароль и блокировка после пяти попыток (`06`, `07`).

## Ошибка по ходу работы

Когда добавила проверку токена, страница ошибки 403 упала с `ReferenceError: user is not defined`: проверка токена стояла раньше, чем подстановка пользователя в шаблоны. Поменяла порядок в `src/app.js`. Разбор в практике 5.
