# Практика 5. Поиск информации и разбор ошибок

Справочник для работы: документация проекта в `node_modules` (README express, ejs, better-sqlite3 лежат на диске, без интернета) и сайты документации. Сайты открывала 05.11.2026.

## Что нашла в справочнике

| Источник | Что узнала |
|---|---|
| expressjs.com/en/guide/error-handling.html | Обработчик ошибок отличается от обычного четвёртым параметром `(err, req, res, next)` и стоит после всех маршрутов. Ошибки в синхронном коде Express ловит сам. Без собственного обработчика клиенту показывается стек, в режиме production стека нет |
| `node_modules/express/lib/application.js` (функция `app.listen`) | В Express 5 функция, которую передали в `listen`, вызывается и при ошибке запуска, ошибка приходит первым аргументом |
| sqlite.org/rescode.html | Код 19 (`SQLITE_CONSTRAINT`) значит нарушение ограничения: уникальность, внешний ключ, NOT NULL. Подробности в расширенных кодах |
| github.com/WiseLibs/better-sqlite3, файл docs/api.md | Ошибки базы приходят как `SqliteError` с полем `code`, например `SQLITE_CONSTRAINT_UNIQUE`; запросы `prepare(...)` с параметрами `?` |
| cheatsheetseries.owasp.org, Session Management | После входа идентификатор сессии надо менять; HttpOnly закрывает cookie от скриптов страницы |

## Ошибки и исправления

1. **Порт занят.** Запустила второй сервер при работающем первом. Консоль написала «Портал запущен» и просто закрылась, хотя сервер не запустился (`01-порт-занят-до.png`). Причина нашлась в `app.listen`: в Express 5 ошибка приходит в функцию, а я её не проверяла. Теперь функция смотрит на ошибку и для `EADDRINUSE` пишет, что порт занят и как сменить (`02-порт-занят-после.png`). Коммит «Практика 5: понятное сообщение, если порт занят».
2. **`ReferenceError: user is not defined`** на странице ошибки 403 (текст ошибки в `server-error.txt`, снимок `03`). Страница ошибки подключает шапку, а шапка использует `user`. Проверка токена формы стояла в `app.js` раньше, чем подстановка пользователя, поэтому при 403 переменной ещё не было. Поменяла порядок: сначала `loadUser`, потом `csrf`. Исправление вошло в коммит практики 4.
3. **Ошибки базы.** Проверила в консоли `sqlite3`, как база реагирует на неверные данные (`04-ошибки-sqlite.png`): опечатка в названии столбца (`no such column: start_at`, в таблице `starts_at`), заявка на несуществующего пользователя (`FOREIGN KEY constraint failed`), логин `admin` повторно (`UNIQUE constraint failed: users.login`). Эти сообщения воспроизвела в консоли специально, из кода они не приходили. По документации ошибка уникальности в Node имеет код `SQLITE_CONSTRAINT_UNIQUE`, поэтому регистрация теперь ловит его и показывает «Такой логин уже занят» вместо страницы 500. Коммит «Практика 5: дубль логина из базы показывается как ошибка поля». Поведение закреплено тестами `tests/db.test.js`.
